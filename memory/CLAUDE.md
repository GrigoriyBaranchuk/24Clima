# LLM Wiki — схема памяти проекта 24clima

> Реализация паттерна Andrej Karpathy «LLM Wiki»
> (https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f).
> Этот файл — **схема**: он объясняет агенту, как устроена вики, какие
> соглашения действуют и какие операции над ней выполняются.
> Читается автоматически при работе с любым файлом в `memory/`.

## Зачем это нужно

`PROJECT_MEMORY.md` — хронологический журнал сессий: он растёт линейно и
отвечает на вопрос «что делали». Вики отвечает на вопрос «как сейчас
устроено и почему»: знание накапливается и **уплотняется**, а не копится
дописыванием в конец.

Разделение обязанностей:

| Файл | Роль | Кто пишет |
|---|---|---|
| `PROJECT_MEMORY.md` | лог сессий, хронология | человек + агент, append |
| `memory/wiki/**` | сжатое актуальное знание | агент, перезапись страниц |
| `memory/raw/**` | неизменяемые источники | человек, только добавление |

Вики **не дублирует код**. Если факт выводится чтением файла в `src/` —
ему место в вики только тогда, когда он неочевиден: причина решения,
подводный камень, договорённость, бизнес-факт.

## Структура

```
memory/
├── CLAUDE.md            # этот файл — схема и правила
├── raw/                 # НЕИЗМЕНЯЕМЫЕ источники (агент читает, не правит)
└── wiki/
    ├── index.md         # каталог всех страниц с однострочными аннотациями
    ├── log.md           # append-only журнал операций (ingest/query/lint)
    ├── entities/        # люди, компании, сервисы, внешние системы
    ├── concepts/        # подсистемы, механики, соглашения проекта
    ├── sources/         # по одной странице на каждый заингестенный источник
    └── synthesis/       # ответы на вопросы, разборы, сравнения
```

### Что попадает в `raw/`

Внешние материалы, которых нет в репозитории и которые нужно сохранить
дословно: выгрузки GSC/DataForSEO, ответы Google-поддержки, ревью codex,
скриншоты SERP, письма клиентов, конкурентные страницы. Формат: подпапка
по типу, имя файла `YYYY-MM-DD-краткий-слаг.<ext>`.

Файлы репозитория (`src/**`, `docs/**`, `PROJECT_MEMORY.md`) **не
копируются** в `raw/` — они и так под гитом. Источник-страница ссылается
на них путём.

**Агент никогда не редактирует и не удаляет `raw/`.**

## Схема страницы

Каждая страница вики начинается с YAML-frontmatter:

```yaml
---
type: entity | concept | source | synthesis
title: Человекочитаемое название
updated: YYYY-MM-DD
sources: [PROJECT_MEMORY.md, raw/gsc/2026-08-01-queries.csv]
related: [concepts/seo-monitoring-system, entities/24clima]
status: current | stale | contested
---
```

- `sources` — откуда взяты факты. Пустой список недопустим: страница без
  источника — это догадка.
- `related` — пути без расширения от `wiki/`.
- `status: contested` ставится, когда на странице есть незакрытое
  противоречие; `stale` — когда факты явно устарели, но замены пока нет.

Тело страницы:

1. **Суть** — 1–3 предложения, что это и зачем.
2. **Факты** — по делу, каждый нетривиальный факт с пометкой источника
   `[PROJECT_MEMORY.md, 2026-07-31]`.
3. **Грабли / ограничения** — если есть.
4. **Связи** — ссылки `[название](../concepts/страница.md)`.

Язык вики — **русский** (язык разработки проекта). Названия файлов,
компонентов, ключей — как в коде, латиницей.

## Соглашения о ссылках

- Только относительные markdown-ссылки: `[SEO-мониторинг](../concepts/seo-monitoring-system.md)`.
- Связь двусторонняя: сослался на страницу — добавь обратную ссылку в её
  раздел «Связи».
- Страница без входящих ссылок (кроме `index.md`) — сирота, ловится линтом.

## Операции

### `ingest` — заингестить источник

1. Прочитать источник целиком. Если он внешний — сначала положить в `raw/`.
2. Обсудить с человеком ключевые пункты, если источник неоднозначный.
3. Создать `wiki/sources/<слаг>.md` — что за источник, дата, ключевые тезисы.
4. Обновить или создать затронутые страницы `entities/`, `concepts/`.
   Один источник обычно затрагивает 3–15 страниц.
5. Проверить **противоречия** с уже записанным (см. ниже).
6. Обновить `wiki/index.md`.
7. Дописать запись в `wiki/log.md`.

### `query` — ответить по вики

1. Сначала прочитать `wiki/index.md`, выбрать релевантные страницы.
2. Прочитать их, ответить **с цитированием страниц**.
3. Если в вики знания нет — сказать об этом прямо, не выдумывать;
   предложить источник, который стоит заингестить.
4. Если ответ ценный и переиспользуемый — сохранить его как
   `wiki/synthesis/<слаг>.md` и внести в индекс.

### `lint` — проверка здоровья

Ищем:
- противоречия между страницами;
- устаревшие утверждения, перекрытые более новыми источниками;
- страницы-сироты (нет входящих ссылок);
- понятия, которые часто упоминаются, но не имеют своей страницы;
- отсутствующие обратные ссылки;
- страницы без `sources` или с `updated` старше полугода при живом коде;
- пробелы, которые закрываются проверкой в коде или веб-поиском.

Результат — отчёт человеку + запись в `log.md`. Правки — отдельной операцией,
не молча.

## Противоречия

Новый факт против старого — **не затираем молча**. В затронутой странице:

```markdown
> **Противоречие (2026-08-10):** раньше здесь было «X» [источник, дата].
> Новый источник утверждает «Y» [источник, дата]. Актуально: Y — потому что …
```

Если непонятно, что верно, ставим `status: contested` и выносим вопрос
человеку. Тихая перезапись противоречащего факта запрещена — история
решений и есть главная ценность вики.

## Когда создавать страницу, а когда дописывать

**Дописать существующую**, если факт уточняет уже описанную сущность,
подсистему или соглашение.

**Создать новую**, если: появилась самостоятельная подсистема/сущность;
тема тянет минимум на 10 строк собственных фактов; на неё уже дважды
сослались из других страниц.

Не плодить страницы на каждый компонент — гранулярность вики
«подсистема / решение / договорённость», а не «файл».

## Формат `log.md`

Append-only, новые записи **сверху**, чтобы свежее было видно первым:

```markdown
## [2026-08-10] ingest | PROJECT_MEMORY.md
Затронуто: entities/24clima, concepts/seo-monitoring-system, …
Примечание: …
```

## Что делать агенту в начале работы над задачей

1. Прочитать `memory/wiki/index.md`.
2. Открыть страницы, относящиеся к области задачи.
3. По завершении задачи — обновить затронутые страницы и `log.md`
   (это `ingest` собственной работы как источника).
