## Память проекта

Два слоя, роли разные:

- `memory/wiki/` — **LLM Wiki**: сжатое актуальное знание «как устроено и почему».
  НАЧИНАЙ ЗАДАЧУ С `memory/wiki/index.md`, дальше открывай релевантные страницы.
  Правила ведения — `memory/CLAUDE.md`. Операции — скилл `/wiki` (ingest/query/lint).
- `PROJECT_MEMORY.md` — хронологический журнал сессий «что делали и когда».

После значимой работы обновляй оба: страницы вики (знание) + запись в журнал (история).

**Политика:** repo-память (`memory/` + `PROJECT_MEMORY.md`) — единственная
каноническая память проекта; только она синхронизируется между машинами.
Локальная память агентов — не-authoritative кэш, проектные факты там не копить.
Черновики итогов сессии можно складывать в `memory/inbox/` (в .gitignore),
в вики они попадают только через осознанный `/wiki ingest`, никаких автокоммитов.

## Протокол сессии (работа с двух машин)

Память проекта синхронизируется между машинами ТОЛЬКО через git. Поэтому:

1. **Старт сессии:** обновись из GitHub — `git fetch --prune && git pull` на main.
   Без этого не видно работу, сделанную на другой машине.
2. **Затем выведи todo-список:** открытые задачи из `PROJECT_MEMORY.md` (секции
   «Осталось»/«TODO»), несмерженные ветки/PR, пробелы из `memory/wiki/index.md`.
   Согласуй с пользователем, что берём в работу.

   **Шаги 1–2 — БЕЗУСЛОВНЫЕ.** Они выполняются в начале КАЖДОЙ сессии до
   старта самой задачи — даже если задача выглядит как «просто обсуждение»,
   read-only анализ или фоновый джоб. Иначе анализ идёт по устаревшему коду
   (грабли №23 в `memory/wiki/synthesis/gotchas.md`).

3. **Конец сессии:** запиши сделанное в оба слоя памяти — страницы `memory/wiki/`
   (ingest, скилл `/wiki`) + запись сессии в `PROJECT_MEMORY.md`.
4. **Домержи запись в main** (ветка → PR → merge): пока запись памяти не в main,
   вторая машина её не увидит. Это правило — про записи памяти; мерж КОДА в main
   по-прежнему только по явному «ok» пользователя.
