# /seo-tasks — рабочий цикл рекомендаций SEO-агента

Цикл: пользователь жмёт ✓ («принять») на дашборде → рекомендация получает `status='accepted'`
в таблице `public.seo_recommendations` (Supabase) → этот скилл забирает их в терминал,
превращает в рабочий документ, а после выполнения ставит `status='done'` + `resolution` +
`done_at`. Выполненные появляются на дашборде во вкладке «Готово» и **засечками на графиках
метрик** (клик по засечке показывает динамику до/после).

## Шаг 1 — забрать принятые рекомендации

Через Supabase MCP (`execute_sql`, проект 24clima — найди через `list_projects`, если ref не в контексте):

```sql
select id, category, severity, title, detail, created_at, updated_at
from public.seo_recommendations
where status = 'accepted'
order by case severity when 'critical' then 0 when 'warning' then 1 else 2 end, created_at;
```

Если пусто — сказать пользователю «принятых рекомендаций нет, прими их на
https://24clima.com/ru/consejos-y-guias/admin/seo/» и остановиться.

## Шаг 2 — собрать рабочий документ

Записать в `tmp/seo-tasks-<YYYY-MM-DD>.md` (каталог `tmp/` в корне репо; создать при
отсутствии; в git не коммитить — это временный промт). Формат:

```markdown
# SEO-задачи от агента — <дата>

## [id <N>] <title>   (severity, category)

**Что говорит агент:** <detail целиком>

**План:** <2-5 конкретных шагов: какие файлы/страницы, что менять>
**SEO-review:** нужен / не нужен (см. шаг 3)
**Критерий готовности:** <как проверим, что сделано>
```

Показать документ пользователю и согласовать порядок, если пунктов больше одного.

## Шаг 3 — выполнение

Для каждого пункта:

1. Если правка затрагивает **protected SEO elements** (метаданные, title/description,
   JSON-LD, hreflang, canonical, sitemap, robots, hero/CTA, анимации, новые
   страницы/роуты — полный список в `.agents/skills/24clima-seo-guide/`) — сначала
   прогнать план правки через сабагента **seo-reviewer** и выполнить его условия.
2. Работать по обычным правилам проекта (CLAUDE.md): worktree, build-проверка,
   никаких push без явного «ok» пользователя.
3. Чисто контентные/внешние задачи (например, «завести Google Business Profile») —
   не кодовые: подготовить материалы и отдать пользователю, пункт НЕ закрывать
   как done, пока пользователь не подтвердит.

## Шаг 4 — закрыть выполненный пункт

Только после того, как работа реально сделана и проверена (для кодовых задач —
закоммичена; если деплой ещё не случился, честно писать это в resolution):

```sql
update public.seo_recommendations
set status = 'done',
    resolution = '<1-3 предложения: что именно сделано; commit <sha>; страница/PR>',
    done_at = now(),
    updated_at = now()
where id = <N> and status = 'accepted';
```

Правила:
- Обновлять **только по конкретному id**, никаких массовых update.
- `where ... and status='accepted'` обязателен — не перетирать статус, изменённый с дашборда.
- В `resolution` всегда включать commit sha (или ссылку на PR/страницу) — он
  показывается на дашборде в карточке засечки.
- В БД стоит constraint `seo_reco_done_at_consistency`: `done` ⇔ `done_at is not null`.
  Не пытаться его обходить.

## Шаг 5 — итог

Перечислить пользователю: что закрыто (id + заголовок + commit), что осталось в
accepted и почему. Напомнить, что засечки на графиках появятся сразу, а эффект в
метриках — с лагом (GSC ~2 дня, SEO-эффект — дни/недели).
