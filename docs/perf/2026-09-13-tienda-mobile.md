# /tienda на мобильном: замер до/после (2026-09-13)

Часть B плана `24clima-shop/docs/research/2026-09-13-merchant-quality/PLAN.md`
(B1 стриминг каталога, B2 аналитика после взаимодействия, B3 фильтр фото в фиде).
Повод: Merchant Center просит «сократите время загрузки мобильного сайта до 2,5 с».

## Как мерили

- `npm run build` + `npm run start` на `localhost:3111`, данные — живой прод-API
  (`API_PROXY_TARGET=https://api.shop.24clima.com`, только чтение).
- Lighthouse 12, mobile, `--throttling-method=simulate`, `--only-categories=performance`,
  headless Chrome. По 3 прогона на страницу, в таблице — медианы.
- «До» — состояние `origin/main` (331a023), «после» — ветка `feat/tienda-mobile-speed`.
- Замер локальный: сеть до статики нулевая, поэтому абсолютные цифры ниже прод-замера
  из плана (там /tienda LCP 8,0 с, TBT 3,8 с, perf 38). Сравнивать имеет смысл дельты.

## Что дало эффект

- **TBT** — целиком B2. В прогоне «до» Lighthouse успевал подтянуть
  `fbevents.js`, `gtag/js`, `mc.yandex.ru/metrika/tag.js` и `merchantwidget.js`
  (requestIdleCallback с timeout 3 с срабатывал прямо в окно измерения).
  В прогоне «после» третьих сторон в трассе нет ни одной.
- **Стриминг (B1)** в этих цифрах почти не виден: API отвечает за ~50 мс из кэша
  `next.revalidate`, поэтому каталог успевает в первый флеш. Эффект проверен
  отдельно — с искусственной задержкой 2 с в `HomeCatalog`:
  оболочка + H1 уходят на 331 мс, каталог дострикивается на 2270 мс
  (до правки весь ответ ждал бы API целиком). Это и есть страховка от медленного
  или холодного бэкенда, из-за которого на проде LCP был 8 с.
- **LCP** не изменился: элемент LCP — H1, а в симуляции Lighthouse его отрисовка
  упирается в скачивание всего HTML (~145 КБ) и render-blocking CSS, не в JS.
  Дальнейший шаг здесь — размер HTML/CSS, он вне части B.

## Проверка поведения третьих сторон

Headless Chrome с `--virtual-time-budget`, без единого взаимодействия:

| Момент | Что в DOM |
|---|---|
| 6 с | только инлайн-заглушка `meta-pixel-stub` (сеть не трогается) |
| 20 с | сработал запасной таймер 10 с: `fbevents.js`, `gtag`, Метрика, `merchantwidget.js` |

`window.fbq` с очередью существует с момента гидратации, поэтому `metaPixelEvent`
до загрузки библиотеки не теряет событие — оно уйдёт, когда приедет `fbevents.js`.

## Решения

- **loading.tsx для /tienda не добавляю.** `TiendaShell` (шапка, футер, BottomNav)
  живёт внутри страницы, а не в layout, поэтому route-level загрузка показала бы
  скелет без хрома сайта. При клиентской навигации оболочка приезжает за ~300 мс —
  этого мало, чтобы платить мигающим макетом.
- **Главное фото в фиде не фильтруем по размеру** (B3): его выбирает API
  (`clean_primary_image_url`), а оффер без картинки Google отклоняет целиком.
