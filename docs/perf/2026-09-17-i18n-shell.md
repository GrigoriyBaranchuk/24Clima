# Словарь переводов в HTML: сужение оболочки (2026-09-17)

Продолжение PR #77. Принцип владельца: **каждая страница везёт только те
неймспейсы переводов, которые нужны её клиентским компонентам**; новая фича
заводит свой неймспейс и не расширяет оболочку.

## Что сделано

- `CLIENT_SHELL_NAMESPACES` сузились до `common` + `whatsappMessages` — ровно
  того, что читают Header, BottomNav и DesktopWhatsAppFab на любой странице.
- Остальные девять (`calculator`, `packages`, `contact`, `contactForm`,
  `whyUs`, `problems`, `homeCta`, `nosotrosCta`, `tips`) выделены в
  `PUBLIC_SITE_CLIENT_NAMESPACES` — клиентские тексты публичного маркетингового
  сайта. Их отдают корневые layout-ы обоих деревьев.
- `tienda.cart` ушёл из оболочки в провайдер магазина.
- Провайдеры роутов: `/tienda/**` → `[...SHELL, "tienda"]`;
  `/servicios/[service]` → `[...SHELL, ...PUBLIC_SITE, "services"]` (страница
  чистки рендерит CleaningPackages и Calculator); `/consejos-y-guias/admin` →
  `[...SHELL, "tipsAdmin"]`.

## Замер

Метод: из HTML склеиваются куски RSC-payload `self.__next_f.push([1,"…"])`,
разэкранируются, из них по балансу скобок вырезается каждый объект
`"messages":{…}`. Считается длина в байтах UTF-8 уже разэкранированного JSON —
одинаково для прода и для локальной сборки. Мобильный UA.

«Было» — прод https://24clima.com (main, PR #77). «Стало» — локальный
`next build` + `next start` этой ветки.

### Почему выигрыш такой маленький — и где на самом деле лежат 6,8 КБ

В плане ожидалось, что `/tienda/` похудеет с ~8,6 до ~1,8 КБ. Замер показал две
вещи, которых в плане не было.

**1. Вложенный провайдер и так почти ничего не стоил.** React-Flight дедуплицирует
одинаковые объекты внутри payload: неймспейсы, попавшие и в корневой, и во
вложенный провайдер, во втором были ссылками по ~30 Б, а не копиями. Разбивка
прода по `/tienda/`:

```
провайдер 1 (корневой): 7946 Б — common=955 whatsappMessages=375 calculator=687
  packages=914 contact=612 contactForm=648 whyUs=848 problems=1609 homeCta=308
  nosotrosCta=189 tips=224 tienda=429
провайдер 2 (магазин):  7186 Б — common=27 whatsappMessages=37 calculator=31
  packages=29 contact=28 contactForm=32 whyUs=26 problems=29 homeCta=28
  nosotrosCta=32 tips=25 tienda=6714
```

То же место после изменения:

```
провайдер 1 (корневой): 7507 Б — common=955 whatsappMessages=375 calculator=687
  packages=914 contact=612 contactForm=648 whyUs=848 problems=1609 homeCta=308
  nosotrosCta=189 tips=224
провайдер 2 (магазин):  7207 Б — common=27 whatsappMessages=37 tienda=7102
```

Маркетинговые ссылки из провайдера магазина исчезли, но они и весили ~320 Б на
всех. Реальный выигрыш — 439 Б от выноса `tienda.cart` из оболочки, и он
достаётся КАЖДОЙ странице сайта, включая главную.

**2. Корневой провайдер сериализуется и на `/tienda/**` тоже.** Корневой
layout — родитель всех роутов, его `messages` уезжают в payload независимо от
того, что вложенный провайдер их замещает для потомков. Поэтому 6,8 КБ
маркетингового словаря всё ещё лежат в HTML страниц магазина: сузить оболочку
было необходимо, но недостаточно.

### Что закроет остаток

Вынести маркетинговые страницы в route-group `(marketing)` с собственным
layout-провайдером, а корневым layout-ам оставить только
`CLIENT_SHELL_NAMESPACES`. Это перенос ~13 папок в двух деревьях роутов — цена,
от которой на этом шаге сознательно отказались (вопрос 1 плана). После него
`/tienda/` уедет к ожидаемым ~1,8 КБ, а список `PUBLIC_SITE_CLIENT_NAMESPACES`,
заведённый здесь, станет содержимым провайдера этой группы — то есть подготовка
уже сделана.
